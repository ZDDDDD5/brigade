# 中文工作台更新说明

2026-11-25 · 基于 Brigade 0.6.0，上游基线 `718aefad`。本次交付阶段 0 至 2。

## 使用方法

| 功能 | 入口与操作 |
| --- | --- |
| 整理侧栏 | 在侧栏「队友」一节，点「固定群聊」右侧的整理按钮。可以置顶队友或群聊、新建或改名分组、调整显示顺序。点「保存整理」生效。 |
| 收起或退出分组 | 点组名折叠；在整理窗口把成员移到「未分组」，或点「解散分组」。队友、群聊和历史继续保留。置顶项目显示在置顶区，取消置顶后回到所属组。 |
| 建立固定群 | 打开「固定群聊 → 新建群聊」，选至少两位队友，再从中选群管理员。只有一位队友时，可在建群窗口创建另一位。同一位队友可加入多个群。 |
| 发任务 | 打开群页，填写「布置任务」，选择已在线的本机 Runner。普通任务由管理员先接单。点一个或多个成员按钮可指定接单人，每条消息最多点名五位。 |
| 查进展、继续聊 | 每次在群页发送都会建立一条独立任务对话。群任务卡展示负责人、状态、待确认项和最近回复。点「对话、审批与文件」查看完整记录、交付物或继续同一个任务。群任务中的普通追问也交给当前管理员。 |
| 停止与重试 | 活跃任务可点「停止任务」中断当前回合、取消排队的接力。已停止的任务可点「继续任务」；失败回合可点「重试失败回合」，沿用 Brigade 的重试机制。 |

分组和排序按工作区及当前成员保存在服务端，换浏览器仍可读取。首次升级的账户沿用原有队友和顺序。固定群首版面向一位用户和多位 Bot。每位用户管理自己的群目录，群任务沿用 Brigade 原有对话的可见性与操作权限。管理员是群中的调度角色，执行仍遵守队友原有账号、额度和审批规则。群任务页每五秒刷新当前页，每张卡最多预览八条回复，完整内容在任务对话内。

## 中文版构建与升级

使用 Node.js 24 和仓库指定的 pnpm 10.34.6。下面示例适用于已有 Brigade API、PostgreSQL 和 Runner 的部署。在仓库根目录执行，先备份数据库，等正在运行的回合结束。

```sh
corepack pnpm install --frozen-lockfile
corepack pnpm -r --filter '@brigade/web^...' --filter '@brigade/api^...' --filter '@brigade/runner^...' run build
corepack pnpm --filter @brigade/api build
corepack pnpm --filter @brigade/runner build
corepack pnpm build:zh
corepack pnpm --filter @brigade/api exec prisma migrate deploy
```

API 按现有方式读取 `apps/api/.env`。迁移 `20261125120000_team_rooms` 新增群表、任务关联和个人布局字段。升级后重启 API 和 Runner，把原 Web 启动命令替换为 `node scripts/zh-cn/start.mjs`。中文 Web 默认监听 `127.0.0.1:3002`，构建默认使用同源网关 `http://127.0.0.1:3000`。不同部署在**构建时**设置 `NEXT_PUBLIC_API_URL`，在**启动时**设置 `PORT`。API 的 `WEB_URL` 应包含浏览器实际访问的地址。首次配置自部署所需组件请参见 [Brigade 本地安装指南](../README.md#run-it-locally)。

英文工作台和中文补丁分别保存在 `apps/web` 和 `scripts/zh-cn/workbench.patch`。构建脚本从 Git 跟踪的文件制作独立副本并应用补丁。上游修改了补丁依赖的英文段落时，构建会报告具体文件和补丁位置；在合并上游时也应检查新页面的英文文案。只有 Next.js 构建成功后才会切换 `.brigade-build/current`。回退时可重新指向上一个中文构建并重启 Web，API 和 Runner 可切回上一版；保留新增数据库表和字段即可保留群资料。

## 验证记录

- 从独立 Git 检出按锁文件安装依赖，构建中文生产包，并在全新数据库迁移、官方样例工作区和模拟 Runner 上启动。
- 浏览器实际创建三位队友的固定群，普通任务得到三份署名回执。点名 Riley 的另一条任务只有 Riley 回复，任务卡可打开原对话。刷新后置顶和折叠状态保留，分组可以改名和解散。
- API 的 40 项测试覆盖个人及工作区隔离、过期布局更新、任务首发与重复投递、点名与交接、停止、恢复、失败重试，以及原有单聊和首次设置流程。Runner 的 12 项测试覆盖停止后的队列、显式恢复及多队友轮转。
- 三位 Bot 的验收回复来自模拟 Runner，测试过程无需调用付费模型。实际回复质量、时延和额度取决于本机账号及所选模型。
